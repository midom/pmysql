# pmysql

Runs one query against many MySQL servers in parallel. Reads a server list on stdin
(or `-X file`), writes tab-separated rows on stdout. ~1400 lines of C over glib and
libmysqlclient.

## Build

```sh
make                                                   # whatever mysql_config is on PATH
make MYSQL_CONFIG=/usr/local/mysql/bin/mysql_config     # a specific client install
```

`MYSQL_CONFIG` also drives the rpath, so a binary built against a non-system client
runs without `LD_LIBRARY_PATH`. Verify with `ldd pmysql | grep mysqlclient`.

Builds warning-free at `-Wall -Wextra`. Keep it that way — in particular
`-Wimplicit-fallthrough` is **on**, and the async state machine's deliberate
fallthroughs are marked with `PMYSQL_FALLTHROUGH`. If you add a `case` there, mark
it; don't silence the warning globally.

Async support compiles in only when `MYSQL_VERSION_ID > 80016` (`PMYSQL_ASYNC`).
Older clients build a working binary where `-Z` reports "Async I/O not supported".
`./pmysql --version` reports which way it went, alongside the git revision and the
client library — check it first when `-Z` behaves unexpectedly:

```
pmysql d523e3c-dirty, committed 2020-06-22 03:44:09 +0000
async I/O:    available (-Z)
MySQL client: 8.0.46 (built against 8.0.46)
glib:         2.80.0 (built against 2.80.0)
```

`version.h` is generated by the Makefile from `git describe` / `git log`. It is
rewritten only when the git state changes, so `make` twice in a row recompiles
nothing. A tarball with no `.git` (or compiling `pmysql.c` without make at all)
degrades to `unknown` rather than failing. It is a build artifact — `make clean`
removes it, don't commit it.

`make format` needs clang-format; `.clang-format` is checked in (2-space, 80 col).

## The one thing to know: two execution paths

Every feature exists twice.

- **threaded** (default): `run_job` → `run_query`, one `GThreadPool` worker per job,
  200 threads unless `-t`.
- **async** (`-Z`): `run_query_async_cb`, a resumable state machine over
  `mysql_*_nonblocking`, `get_nprocs()` event-loop threads from `threadpool.c`.

**They must produce identical output for identical input.** Historically they didn't,
and every divergence was a bug. When you touch behavior in one, change the other and
diff them:

```sh
echo "127.0.0.1:3306" | ./pmysql    -u U -p P <flags> "SELECT ..." > /tmp/sync
echo "127.0.0.1:3306" | ./pmysql -Z -u U -p P <flags> "SELECT ..." > /tmp/async
diff /tmp/sync /tmp/async
```

Shared logic belongs in a helper both call — `job_seed_dblist()` is the model.

## Async state machine invariants

`run_query_async_cb` is re-entered from the top on every resume, dispatching on
`je->state`. Two rules follow:

1. **Any `case` can run many times.** Work that must happen once per entry must be
   guarded by the state transition, not just placed in the case body:
   ```c
   if (je->state != JOB_FETCH_DATABASES) {
     je->state = JOB_FETCH_DATABASES;
     /* one-shot work here */
   }
   ```
   Building a list unguarded means rebuilding it once per network round trip.

2. **Distinguish all three `net_async_status` values.** `if (ret != NET_ASYNC_COMPLETE)
   return park(je);` also parks on `NET_ASYNC_ERROR`, and since the dead socket stays
   readable that becomes a busy-spin that only ends if `--read-timeout` is set. Check
   `NET_ASYNC_NOT_READY` and `NET_ASYNC_ERROR` separately.

`park()` re-arms the job and returns FALSE; the caller must `return park(je)`.
It watches `G_IO_ERR|G_IO_HUP` on the socket, so a **NULL `source`** is what
distinguishes a timer firing from the peer hanging up — see the comment at the top of
the callback before changing either.

`free_job()` is the single exit for both paths: releases the `-t` semaphore slot,
flushes buffers, closes the handle. Every error path calls it and returns FALSE.

## Output buffering

`print_row` appends into two `GPrivate` (per-thread) GStrings and flushes at 16 KB.
In async mode many jobs share one thread, so `park()` calls `flush_buffers()` before
yielding — otherwise rows from different servers interleave mid-line. Anything that
can yield must flush first.

## Testing against a local server

MySQL 9.x clients dropped `mysql_native_password`, so create the test user with
`caching_sha2_password` or connections fail with a confusing plugin-load error:

```sh
sudo mysql -e "CREATE USER 'pmt'@'%' IDENTIFIED WITH caching_sha2_password BY 'pmtpass';
               GRANT ALL ON *.* TO 'pmt'@'%'; CREATE DATABASE dbA;"
echo "127.0.0.1:3306" | ./pmysql -u pmt -p pmtpass "SELECT VERSION()"
```

To exercise async **parking** (where the re-entrancy bugs live) the result set must
be big enough to span several round trips — a handful of rows completes in one go and
tests nothing. Several hundred databases via `-A`, or a few thousand rows, does it.

Timeouts are worth re-checking after any `threadpool.c` change:
`-T 2` against a blackhole IP (10.255.255.1) should fail in ~2s; `-R 1` with
`SELECT SLEEP(5)` should fail in ~1s.

### Sanitizers

```sh
cc -Wall -Wextra -g -O1 -std=c11 -fsanitize=address,undefined -fno-omit-frame-pointer \
   $(mysql_config --cflags) $(pkg-config glib-2.0 gthread-2.0 --cflags) \
   pmysql.c threadpool.c \
   $(mysql_config --libs_r) $(pkg-config glib-2.0 gthread-2.0 --libs) -o pmysql_asan
```

A clean run still reports ~20 leaked allocations, all from `main` — the fake
`mysql_real_connect(CLIENT_REMEMBER_OPTIONS)` handle that harvests my.cnf defaults is
deliberately never closed outside `#ifdef DEBUG`. Judge changes by *delta* against the
same binary built from HEAD, not by the absolute number; it also shifts with the
client library version. Leaks attributed to `run_job` / `run_query_async_cb` /
`free_job` are real.

Do **not** set `ASAN_OPTIONS=fast_unwind_on_malloc=0`. With 200 threads it makes the
slow unwinder segfault with an empty stack at startup, which looks exactly like a
crash in pmysql and is not one.

## Gotchas

- `mysql_get_socket_descriptor` is hand-rolled for non-Facebook clients by
  redeclaring `struct Vio` (bug #99805). It depends on `fd` being first in `Vio`.
  Re-check on client upgrades.
- `main` reads `mysql->options.{user,password,port,unix_socket}` directly out of the
  client struct to inherit my.cnf defaults. Private API; can break on upgrades.
- `--help` documents the input and output formats via `INPUT_OUTPUT_HELP`, right
  above the option table. It is a hand-written string: changing `read_job` or
  `print_row` means editing it too, or the help starts lying.
- `read_job` autodetects 1–4 columns and `-x/--tagged` changes what column 3 means.
  Empty columns must normalize to NULL *before* the two-column early return, and
  empty server names must be skipped — libmysqlclient silently treats an empty host
  as localhost, so a stray newline would query the local machine.
- SSL mode is only sent when non-zero: `0` is not a valid `enum mysql_ssl_mode`
  (the enum starts at `SSL_MODE_DISABLED = 1`).
- `-B a,b` becomes the global `databases` array and `db` is set to NULL; a single
  `-B a` stays in `db` and is selected at connect time. `job_seed_dblist` depends on
  that split.
